# 文档质量检查规范 (Quality Checklist)

## 4.1 三级检查体系

### 一级：完整性检查 (Completeness)
- [ ] 标题是否包含核心关键词"彼得潘"、"简爱"、"成长"？
- [ ] 摘要能否独立成篇？（不看正文是否完整）
- [ ] 每个提纲节点都有对应内容？（无悬空标题）
- [ ] 结论是否回应了摘要中提出的问题？
- [ ] 原文引用是否标注具体章节或页码？

### 二级：一致性检查 (Consistency)
- [ ] 术语全文统一（如"永无岛"不写作"梦幻岛"，"桑菲尔德"不简写）
- [ ] 数据前后一致（如人物关系、情节发展）
- [ ] 时态统一（回忆书中内容用现在时，个人经历用过去时，规划用将来时）
- [ ] 人称统一（全文使用"我"，禁止"我们/笔者"混用）
- [ ] 标点规范（中文正文用全角标点，英文术语保留半角括号）

### 三级：有效性检查 (Effectiveness)
- [ ] 每章删除测试：删除该章是否损害整体理解？如否，则该章冗余
- [ ] 反向阅读测试：从结论倒推，论据是否足够支撑？
- [ ] 陌生人测试：假设读者是领域外人士，是否有概念未解释？
- [ ] 时间胶囊测试：三年后重读，是否仍能理解核心观点？
- [ ] 行动导向测试：读者读完后能采取什么具体行动？

## 4.2 题材特化检查项（读书心得）
| 检查维度 | 具体要求 |
|---------|---------|
| 原文引用占比 | 直接引用不超过全文15%，避免沦为摘抄 |
| 个人思考占比 | 个人感悟与分析不少于全文60% |
| 跨学科关联 | 软件工程视角的思考不少于全文20% |
| 对比分析深度 | 两书对比不少于3个维度，每个维度有具体例证 |
| 行动转化 | 必须包含可量化的行动清单，不少于3条 |

## 4.3 评分与迭代机制
- **基线分**：满分100，一级检查每项15分，二级每项10分，三级每项5分，特化检查项每项5分
- **通过标准**：≥85分可输出；70-85分需标注待改进项；<70分重写
- **迭代指令**：若未通过，使用"基于[具体检查项]的反馈，请修正[具体位置]，要求[具体标准]"

## 4.4 常见失败模式 (Anti-patterns)
| 模式名称 | 症状 | 修复策略 |
|---------|------|---------|
| 头重脚轻 | 背景写3页，结论2句话 | 强制结论区字数≥摘要区×2 |
| 概念通货膨胀 | 堆砌术语无实质内容 | 每个术语必须跟"也就是说..."的解释句 |
| 情感透支 | 形容词密度>20% | 将所有"非常/极其/深刻"替换为具体程度副词或数据 |
| 正确的废话 | "我们要努力学习" | 加入主语、时间、衡量标准："我计划每天阅读30分钟" |
| 逻辑跳跃 | "因为A，所以C"缺B | 强制补充中间环节，或使用"这意味着..."过渡 |
| 对比失衡 | 详细分析一本书，另一本书沦为陪衬 | 强制每章两书内容篇幅比例不超过2:1 |
| 技术强行植入 | 生硬套用技术术语，与文学分析脱节 | 技术类比需自然，服务于文学解读 |

## 4.5 字数检查
- [ ] 全文字数≥3000字
- [ ] 摘要字数占比5-10%（约150-300字）
- [ ] 主体论证占比60-70%（约1800-2100字）
- [ ] 结论与行动占比10-15%（约300-450字）
